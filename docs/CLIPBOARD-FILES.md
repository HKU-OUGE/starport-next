# 图片剪贴板与文件窗口

| 操作 | Linux / Xpra | Windows / WSLg |
| --- | --- | --- |
| 主机与项目复制文字、图片 | 显式选择 `text-image`；PNG / JPEG | WSLg 文字；Windows 图片自动转换为 PNG |
| 独立文件管理器 | 客户端 → Xpra 无缝窗口 → 文件管理器 | 客户端 → WSLg 窗口 → 文件管理器 |
| 项目应用之间拖文件 | 从文件管理器拖到同一项目的浏览器或编辑器 | 同左 |
| 主机上传／取回文件 | 打开项目文件夹（限定项目的 SSHFS） | 打开项目文件夹（限定项目的 WSL 路径） |
| 网页拖入 | 项目文件区支持批量文件；写入当前目录 | 同左 |

文件管理器使用 Thunar，起始目录 `/workspace`，与该项目的图形应用共用运行边界。不会挂入整个主机 HOME、磁盘或管理凭据。**WSLg 与 Windows 任意窗口之间的直接拖放尚未实现**；同一项目的 Linux 窗口之间可以拖放。客户端页的「Windows 文件窗口」打开当前项目的 Windows 文件资源管理器：从这里拖到其他 Windows 应用，或从 Windows 拖入这里，再从项目文件管理器拖到 Linux 应用。

## Windows 图片 Ctrl+V

明确启用 WSLg 后，控制端在项目图形会话运行期间启动隐藏的当前用户剪贴板监听器。它将 Windows 位图转换为 PNG，经现有项目控制管道分块传入；项目内 GTK 剪贴板拥有者提供 `image/png`，浏览器和 Desktop 仍使用普通 Ctrl+V。默认 X11/XWayland 路径是主要验收对象；Wayland 必须另测。

这是对 [WSLg 的 Windows→X11 图片格式缺失](https://github.com/microsoft/wslg/issues/236) 的兼容处理，不修改 WSLg 系统镜像。普通文字和 Linux→Windows 图片仍使用系统通道。监听器不记录历史、不写图片文件、不读取文字内容；最后一个 WSLg 会话关闭或控制端退出后停止。网页桌面、QEMU、Xpra 与普通 SDK 执行不启动此监听器。多个 WSLg 项目仍共用已经授权的系统剪贴板。

单张图片上限 16 MiB、3200 万像素；只接收带长度与 SHA-256 校验的 PNG，不接收文件路径或任意命令。超限图片改用文件传输。状态接口 `runtime.windowsImageClipboard` 只返回阶段、成功次数和错误类别，不含图片或剪贴板内容。

已有安装需要空闲时更新控制端和 WSL 项目运行包，使用受控客户端安装入口补齐 `python3-gi`、`gir1.2-gtk-3.0`，再重新验证边界并打开项目窗口。不能只替换 Windows 端代码而沿用旧运行包。

## 开启图片剪贴板

Linux 安装向导选择“无缝窗口”和“文字与图片剪贴板”。已有安装在自己的私有控制配置中设置：

```json
{
  "seamless": true,
  "seamlessClipboard": "text-image"
}
```

仍可选 `text`（仅文字）或 `disabled`（关闭）。旧配置不会自动升级共享范围。启用后，复制的文字和图片可以被另一侧读取；不传文件 URI、HTML、选中文字产生的 PRIMARY 剪贴板或历史记录。图片上限 16 MiB、3200 万像素；超过上限改用文件传输。

更新控制端与项目运行包后，关闭并重新打开该项目图形窗口，使新格式策略生效。更新不应强行终止正在运行的命令。文件管理器由新版客户端安装脚本安装；旧项目尚无 Thunar 时，先通过受控安装入口更新客户端。

## 文件拖入与下载

- 网页支持一次选择或拖入多个文件，每个不超过 64 MiB；文件夹与更大文件用“打开项目文件夹”。
- 上传开始时固定项目和目录；切换项目不会把后续文件传错位置。
- 同名文件先确认覆盖，传输仍使用 SHA-256。下载按钮沿用完整性校验。
- 原生项目文件夹可用系统文件管理器复制、移动和拖放；不要把它误认为同步了整个主机文件系统。

## 验证边界

本次新增格式策略、配置往返、文件管理器动作路由、批量上传与目录固定回归测试。Windows 原生图片粘贴和跨应用拖放必须在目标 Windows 机器验收；没有把 Linux 测试当作 Windows 实测。macOS 当前没有同等的无缝窗口入口。
