# 实施路线与交付边界

## D0 — 配置基础（已实现）

已实现：可移植配置校验、不可降低的网络与执行边界、AES-GCM 配置包、Pi v1 迁移、新目录导入、加密 vault、离线部署规划、纯状态判定。配置命令本身保持离线。

## L1 — 本地执行链路（已实现，按平台验收）

`packages/runtime` 提供 QEMU 创建／启动／停止、独立受控出口、普通开发命令、完整性校验的文件传输、Agent SDK 安装与会话。硬件加速映射为 Ubuntu KVM、Windows WHPX、macOS HVF；当前实机证据以 [ACCEPTANCE.md](ACCEPTANCE.md) 为准。

本地工作区与各平台安装入口见 [LOCAL-RUNTIME.md](LOCAL-RUNTIME.md)。没有把本地 CLI 验收当作完整网页、DSW 或原生 Desktop 集成完成。

## D1 — 一条可验收的远端链路

范围：一台电脑 + 一个 Linux／DSW 节点 + 一个独立项目环境。

- 复用 Egress Manager 事务及管理通道；针对当前运行时做真实断线测试。
- Starship 提供版本化部署与独立项目环境，官方 Agent SDK 在其中运行。
- 文件工具、插件及子进程纳入同一边界，验证宿主文件／环境／网络不可见。
- 同时验证普通开发命令和一个小计算任务；依赖按指定版本只读挂载。

通过条件：`ACCEPTANCE.md` 中执行、网络、依赖和资源项全部有该节点的真实收据。失败则该能力不可选择。

## D2 — 网页与手机

已实现独立控制面板、项目文件操作、计算服务状态、Access 源站校验和可选 Tunnel 连接器。Windows／WSL2 增加 SDK 单任务与原生客户端入口，见 [Windows 控制端](WINDOWS-HOST.md)。完整会话 UI 与云端初始化仍待以下阶段；当前不把接口测试视为真实 DSW 或公网验证。

- 选定 CloudCLI 的适配方式或复用现有面板组件；先做单个后端会话所有者。
- 完成会话、工具卡片、审批、文件、媒体、模型／effort 和项目分组。
- 四步向导接入 D0 配置库；新增依赖层、任务和上传进度均由后台维护。
- Access + Tunnel 接入，做授权／拒绝、断线恢复、幂等发送和大文件续传验收。

通过条件：电脑和手机可操作同一个后台会话，关闭网页不影响任务，重新连接不重复执行。

## D3 — 原生 Desktop

已加入本地 guest 内的官方 CLI／Linux Desktop 安装、账号模式和受密码保护的本机画面入口。登录浏览器也在 guest 内，不复用宿主浏览器。实际验收状态见 [官方账号客户端](NATIVE-CLIENTS.md)。

Windows 另提供 WSLg 独立窗口，只有显式选择后共享 Windows 显示和剪贴板；客户端仍在项目文件与网络边界内。安装、窗口启动、账号授权与工具调用分别记录，不以其中一项替代其他项。Cowork 不在这条 WSLg 实现的交付范围内。

提供项目内部的 SSH/SFTP 接入。验证自动安装 Agent、终端、文件树、插件、代理与长任务；要求所有路径都不能落到 DSW 宿主。API 网关模式的官方 Remote Control 限制仍保留，通过自建网页提供远程控制。

通过条件：原生 Desktop 的真实操作与越界测试通过。若原生组件必须调用宿主工具，则禁用该能力或采用已验证的替代工具，不能宣称完整兼容。

## D4 — 跨平台安装与单机

- Windows 原生管理程序，系统权限通过原生授权窗口；PATH 更新保留当前进程可用项。
- Linux systemd、macOS launchd、Windows 当前用户登录任务，默认询问，不存管理员密码。
- 本地 microVM 运行时分别验收；普通 WSL 发行版不自动成为“安全沙盒”。
- 引入有摘要签名的发布产物、可恢复下载、安装收据、版本回滚及范围明确的卸载器。

本地依赖安装脚本已提供；系统登录启动、原生发布包与完整生命周期安装器仍待实现。Linux 测试成功不等于 Windows 真实安装成功。

Windows 提供 `setup-control.ps1`、`setup-wsl.ps1`、`setup-wsl-clients.ps1`、`start-control.ps1` 和安装完成后的访问码窗口；不安装 QEMU，不更改现有 WSL 全局配置。WSL2 内层使用独立命名空间、最小挂载与 syscall 策略，Windows 实机导入、发行版重启、文件／网络边界和真实 SDK Write／Read 已通过。Windows 整机冷启动恢复和登录启动未作为通过项。
