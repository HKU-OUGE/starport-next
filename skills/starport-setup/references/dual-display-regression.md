# 双显示模式回归

修改浏览器包装脚本、客户端启动器、图形会话、查看器或快捷方式后，逐项检查 WSLg 与网页模式。
`wayland`、`x11` 必须分别覆盖；网页入口追加的参数可能掩盖 WSLg 默认参数错误。
读取引入故障的提交，不把未经核实的故障归因于软件升级或用户操作。

## 准备

- 保存源码提交、运行时摘要、客户端版本及可重复的测试结果。私有地址、用户路径和身份只放本机收据。
- 查看活动任务与图形会话，保存测试文件。仅在已获准的回归范围内关闭空闲图形会话；不终止用户任务。
- 明确官方登录能否由用户完成。不能登录时继续所有不依赖账号的检查，将真实对话／模型工具调用标为待验。
- 用现有项目验证持久 HOME；不要新建另一份 HOME、复制账号令牌、重置密钥环或禁用 Chromium 沙箱。

## 每种模式都执行

1. 重新通过项目边界检查。运行 Windows Node 测试及 `npm run check`；在实际 WSL 中执行
   `wsl-gui-linux.test.mjs`、`wsl-linux.test.mjs`、`wsl-native.test.mjs` 和 `wsl-browser.test.mjs`。
   Windows 的 Linux 测试跳过不能记作运行时通过。使用独立临时测试目录，不覆盖安装目录。
2. 从交付入口分别启动浏览器、Claude Code 和 Desktop，等待稳定后查看实际画面。
   仅见进程或启动应答不算通过；记录立即退出、白屏、弹窗和程序日志中的明确错误。
3. 浏览器：键盘输入受控 HTTPS 测试地址并刷新，检查实际内容，再检查官方登录页。
   Desktop：欢迎页进入登录页、焦点／键鼠交互。CLI：欢迎／登录菜单、方向键或文本输入。
   不把页面渲染、`loggedIn: false` 或 MCP 配置存在记作账号功能通过。
4. 检查项目 MCP 配置、使用指引和计算节点健康。已登录且获准调用模型时，让每个客户端
   完成一个小文件读写和只读 `compute_health`，核验产物与两端结果；否则分别标记待验。
5. 运行相反显示模式的启动请求，必须拒绝且原会话保留。关闭空闲应用后切换模式，检查
   同一项目测试文件／摘要与客户端配置保留。切换回来后再次启动，检查残留锁与重复进程。

## 网页额外检查

- 分别记录本机网页查看器与真实公网域名；不能以本机截图替代 Cloudflare 后的实际检查。
- 页面首屏有布局与状态。连接查看器后，检查三种应用画面、鼠标、键盘、展开／返回。
- “断开画面”保留进程；重新连接和页面刷新后连接应恢复原窗口。检查连续两次重连，防止旧连接占用。
- 同时只连接一个查看器。第二连接的拒绝不能破坏原连接。票据单次使用、鉴权、Origin 和项目绑定负例须通过。
- 密钥环可能在显示模式切换后重新锁定。先让窗口在当前查看器中可见，再请用户输入原密码。
  用户解锁期间不要抢占查看器或切换模式。不要把缺少解锁误判成网络故障。
- 公网浏览器工具失败时说明具体阻碍；可用真实页面上的链接继续正常导航，但不得绕过安全警告
  或把命令行 HTTP 成功等同于公网画面／键鼠成功。

## 快捷方式与交付

- 用户要求恢复原图标／名称时，恢复外观并保留控制端启动命令；不要恢复已证实失效的发行版直启命令。
- `register-client-shortcuts.ps1` 默认 `-Appearance original`，缓存原图标到本安装状态，避免临时图标消失。
  仅归档收据列出、路径及目标参数均匹配的旧名称；保留可恢复备份，不覆盖用户修改或整目录清理。
- 分别从最终三个快捷方式启动并观察窗口。重复注册不增添重复项；旧自动图标可能由 WSL 重建，
  优先交付桌面与独立 Starport Next 菜单中的持久入口。
- 将六个“客户端 × 显示模式”格子的启动、交互、登录、模型／MCP 结果分别记录，另列公网、重连、切换。
  失败项修复后只重跑相关检查；受账号或工具阻碍的项目明确待验。验证源码、skill，检查敏感信息后 commit、push。
